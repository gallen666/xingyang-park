WHAT · 什么是 OpenX@X™

从"封闭方法论"到"AI + 云开放生态"

DTSI / X-Flow / PDTMM 三大平台的价值不在"独占"，而在"被复用"。OpenX@X 是 AI + 云开发者社区，让复用可以合法、可以变现、可以反哺母平台，让整个生态持续学习、持续演化。

01
开放 API
DTSI 打分、X-Flow 仿真、PDTMM 认证结果查询，全部封装为 REST + GraphQL 双协议。 Python / Node.js / Java 三种官方 SDK——任何一家咨询公司都能 3 天集成到自己的方案里。
02
开放数据接入协议
制定 Park Data Exchange (PDX) 协议 v1.0——园区智慧系统、企业运营 SaaS、政府监管平台 都能按统一协议接入 DTSI 数据中台。第三方 IoT 厂商无需重新对接每家园区。
03
开放场景插件市场
开发者可以为 DTSI 的 35 个 KPI 提供"特色采集插件"（如"通勤舒适度"通过手机加速度算法采集）。 官方评审通过后进入插件市场，按调用次数分成 30%。
ARCHITECTURE · OpenX@X 5 步开放生态方法论

识别 → 接入 → 重构 → 协同 → 演化

Step 1
识别（Discover）
识别 7 方主体的真实需求——政府/资产/运营/企业/科研/员工/居民各自"最痛的一个 KPI"是什么。
Step 2
接入（Connect）
通过 PDX 协议接入各方数据源——园区智慧系统、企业 SaaS、政府监管平台、IoT 传感器。
Step 3
重构（Restructure）
按 7 方 AHP 权重（政府 25.7% · 资产 18.7% · ...）加权成 DTSI 综合指数——重构数据的意义。
Step 4
协同（Collaborate）
用 X-Flow 全局仿真——推演一个动作对 7 方的连锁反应，让部门之间"看到共同的曲线"。
Step 5
演化（Evolve）
基于仿真结果动态调整——每季度重新拟合参数、每年重新校准权重，让系统持续学习。

FAQ · 常见问题 + 在线咨询

对 OpenX@X™ 还有疑问？

Q1. OpenX@X 是不是"OpenAI 那种大模型"？
不是。OpenX@X 是 Open eXtension at X 的缩写——数字化转型方法论的开放扩展生态。 "X"指任何一家园区、任何一位开发者、任何一个场景。名字里的 "Open" 强调 "开源 + 开放 API + 开放协议 + 开放插件市场"，与 OpenAI 无关。
Q2. 商业开发者授权具体包含什么？
分 3 档：
· Starter ¥8 万/年：API 调用 100k/月 · 品牌授权用于内部方案 · 邮件支持
· Business ¥18 万/年：API 无限 · 可对外营销 "基于 DTSI/PDTMM" · 专属技术支持群 · 联合白皮书署名
· Enterprise ¥ 面议：私有部署 · 源码授权 · 联合品牌"XX × OpenX@X"
Q3. 我发布的插件如何变现？
插件在市场上按调用次数 × 每次单价计费——开发者定价，市场分成 30% 给平台、70% 给开发者。 月结算 · 银行转账 / 支付宝对公 · 单个插件年营收 top 3：报告插件 ¥68 万 / 通勤采集 ¥42 万 / 数据大屏 ¥35 万。
Q4. 学术研究计划怎么申请？
发送邮件到 research@openxx.hk，附：
① 高校身份证明；② 研究主题一页 proposal；③ 承诺论文发表致谢 OpenX@X 平台。
审核通过后可访问脱敏数据集 · 免费使用完整 API · 联合发表可署名"荥阳数字经济产业园 OpenX@X 平台"。 历史通过率 76%——门槛不高，主要卡"必须发论文"。
Q5. PDX 协议是什么？和现有协议什么关系？
Park Data Exchange ——园区数据交换的统一协议 v1.0，基于 OpenAPI 3.0 + JSON Schema， 定义 35 个 KPI 的字段字典、传输格式、鉴权方式。兼容 OPC UA、MQTT、Modbus 等现有工业协议—— PDX 是应用层协议，不替代底层传输。Apache 2.0 开源，两个参考实现（Go / Rust）在 GitHub。
